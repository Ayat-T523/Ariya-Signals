InForm — Visual Reference

Chat Design System

Foundations, components, and composition patterns for the Chat component. Neumorphic workspace on glass passive layer — intelligent warmth.

01 · Principles

Two layers, one register

Glass for passive

Sidebar, top bar, profile. Frosted, warm-biased, reacts to wallpaper. Frames the workspace.

Neumorphic for active

Chat surface, inputs, citation panel, cards. Opaque, tactile, grounded — where work lives.

Colour = meaning

Functional palette with fixed semantics. Colour is never decorative in a compliance-critical context.

Scale rationale. The progression 12 / 14 / 16 / 18 / 20 / 24 / 30 / 38 / 48 uses ratios 1.11–1.27 — tighter steps at reading sizes (where subtle hierarchy matters), wider steps at display sizes (where visual distinction matters). Type rules

  • 14px base. Most interface text lives at --t-body-md. Raise to --t-body-lg only for the AI response body where reading comfort governs.
  • --lh-response is reserved. Use 1.75 only for the AI response body. All other body copy uses --lh-body 1.6 or --lh-body-sm 1.55.
  • Labels are always uppercase. --t-label must be paired with text-transform: uppercase and --ls-label 0.07em. Letter-spacing is not applied to any other size.
  • AI response paragraphs are separated by --t-response-paragraph-gap (14px), not by first-line indent or blank lines.
  • Micro is mono. Citation markers and badge counters use JetBrains Mono at --t-micro; never body sans at this size.

05 · Elevation

Five levels · neumorphic for surfaces, hard shadow for overlays

E1–E3 use dual-source neumorphic (light top-left, warm shadow bottom-right) — these are surfaces that live on the workspace. E4–E5 use hard directional shadow — these are surfaces that float above the workspace and need separation from any background beneath them. Translated from Figma dual-source neumorphic and dropdown recipes.

Elevation rules

  • E1–E3 must sit on an opaque neumorphic surface (--bg-elevated or --bg-page). Neumorphic shadows depend on surrounding surface continuity; they do not read on glass.
  • E4 is for on-workspace overlays. Dropdowns and menus attach visually to the workspace via directional shadow, not neumorphic inset.
  • E5 is modal only. Every modal must be accompanied by a scrim (rgba(42, 39, 34, 0.40)) to block interaction with the layer beneath.
  • Never stack E1 inside E2. Elevations are not additive — pick one per surface.
  • Hover lift: E1→E2 or E2→E3. Never skip two levels — the jump reads as broken.
05b · Glow System

Four surfaces earn a glow — everything else stays matte

Glow is an additive highlight — always layered on top of the surface's base shadow, never a replacement. Five glow tokens, four sanctioned locations: input bar focus, top bar ambient, brief item left edge (urgent / info variants), AI response left edge. Used for emphasis and intelligent warmth; overuse flattens the system.

Glow rules

  • Glow is additive. Always layered on top of the surface's base shadow (elevation or inset), never a replacement.
  • Four sanctioned locations only: input bar focus, top bar ambient, brief item left edge (urgent / info), AI response left edge.
  • Every other surface stays matte. Buttons, chips, cards, sidebar items, citation panel, popovers — no glow.
  • Glow always pairs with a structural element — a coloured left border, a focused input, or an ambient float. Glow alone is never the signal; it reinforces one.

Glass has a warm tint bias so the system holds its intelligent-warmth register regardless of wallpaper colour. Each of the four glass roles has a distinct opacity, blur, and shadow — calibrated to its job. Glass is for passive surfaces (frames, menus, tooltips). Neumorphic is for active workspace. Never mix the two on one surface.

07 · States — Focus & Disabled

Single recipe, applied everywhere

Focus and disabled are system states — they aren't redesigned per component. Every focusable primitive uses the same ring. Every disabled primitive uses the same recipe. This is the a11y floor the whole system sits on.

Focus ring

2px teal outline, 3px offset. Visible on keyboard navigation only (:focus-visible) — pointer users don't see it. Inverse variant (cream) for use on teal-filled primary CTAs where the teal ring would vanish.

Button · focused
Primary CTA · focused
Focused input field ›

Contrast: teal on cream = 4.73:1 · cream on teal = 5.26:1 · both pass WCAG 1.4.11 (3:1 UI component min, 4.5:1 AAA).

Disabled

Sunken fill, muted text, shadow removed, cursor not-allowed. Colour does the work — no opacity dimming, which degrades hue semantics for colourblind users. Inputs retain inset to stay visually recessed.

Disabled input field

Contrast: disabled-fg on disabled-bg = 1.58:1 — deliberately below AA. Disabled controls are not expected to meet text contrast (WCAG 1.4.3 excludes them). Supplement with aria-disabled and a tooltip explaining why disabled, so screen readers announce the reason.

18 · Verification

What's grounded, what's judgment, what's gap

Grounded in best practice

  • 4px spacing base (Material, Apple HIG, Carbon)
  • Motion durations 120–480ms range (Material Motion)
  • Standard easing cubic-bezier(0.4, 0, 0.2, 1)
  • Warm-tinted shadows on warm surfaces (neumorphic canon)
  • Single light source top-left, consistent across all elevations
  • 5-level elevation scale with hard-shadow switch at E4 (Material Elevation + popover convention)
  • Functional colour with fixed semantics (Material, Carbon, Polaris)
  • System-level focus ring with inverse variant (WCAG 2.4.7, 2.4.11 — focus visible & not obscured)
  • Disabled by colour, not opacity (preserves hue semantics for colourblind users)
  • WCAG 2.1 AA contrast on every text pair — verified with actual math
  • Body-lg at 18px inside 16–19px reading-research sweet spot
  • 40×40 touch targets pass WCAG 2.5.5 AA

Informed judgment

  • Plus Jakarta Sans selection — fits brief but aesthetic, not tested
  • Type scale ratios 1.11–1.27 (rationalized, not pure modular)
  • Radius scale 6→28 — wider than Material, appropriate for neumorphism
  • Exact hex values within warm-bias constraint
  • Shadow opacity percentages (0.28, 0.32, etc.) — calibrated by eye
  • Motion duration within ranges (120 vs 150 vs 100 — judgment)
  • Neumorphic radii 14–28 vs flat-design conventions
  • Icon sizing within components (14–20px)

Open gaps

  • Colourblind simulation not done (deuteranopia / protanopia) — needs verification in Sim Daltonism or Stark
  • Dark mode not designed (explicit out-of-scope per project direction, worth stating)
  • Wallpaper variants for glass layer presentation (OV3)
  • Italic usage rules not specified — when to italicise what
  • Type families not tested with real medical copy (BTK inhibitor, MENA subgroup, etc. read differently than lorem ipsum)
  • Arabic companion family for multilingual (noted for later, not v1)
  • Motion-reduced (prefers-reduced-motion) fallback not specified
  • Neumorphic shadow behaviour on small screens not tested
  • Elevation behaviour on zoom / high-DPI not tested (shadow blur radii may need scaling)
  • Glass performance with backdrop-filter blur stacked across 3+ layers not profiled

Contrast verification method

All ratios in section 15 were computed using the WCAG 2.1 relative-luminance formula:

L = 0.2126 · R_lin + 0.7152 · G_lin + 0.0722 · B_lin
where R_lin = R/12.92 if R ≤ 0.03928, else ((R + 0.055) / 1.055)^2.4

Contrast = (L_light + 0.05) / (L_dark + 0.05)

AA threshold: 4.5:1 (normal text) · 3:1 (large text / UI component)
AAA threshold: 7:1 (normal text) · 4.5:1 (large text)

Originally failed pairs that were fixed: urgent text on urgent-tint (was 2.56:1 at #C87F1F, now 5.92:1 at #7A4A0F). Approved, returned, error status pills similarly darkened. Text tertiary repositioned as large-text-only.
